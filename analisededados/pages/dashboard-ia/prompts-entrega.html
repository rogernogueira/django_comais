Prompt 4 — Entrega do dashboard

Quarto prompt: CSVs + catálogo → HTML standalone.

O prompt completo

Gere UM arquivo dashboard.html standalone com:

  1. Cabeçalho com título e botão "limpar filtros"
  2. Linha de KPIs no topo (5 cards)
  3. Filtros multi-select: unidade, tema, categoria, impacto, situação
     (KPIs e gráficos reagem em tempo real)
  4. Grid com os 10 gráficos do catálogo da etapa anterior
  5. Tabela detalhada dos itens filtrados, no rodapé

Stack:
  - HTML5 + Vanilla JS
  - Chart.js via CDN (versão estável mais recente)
  - Plugins via CDN quando necessário (treemap, matrix)
  - CSS embutido. Sem build, sem framework.

Critérios:
  - Layout responsivo
  - Paleta acessível (contraste AA)
  - Formatação BR de moeda e data
  - Sem chamadas de rede em runtime exceto os CDNs

Cada gráfico de render() recebe a lista de itens filtrados como
parâmetro. Envolva cada render em try/catch para que um gráfico
quebrado não derrube os outros.

Por que cada parte importa

  • ›Stack explícita: HTML+JS+Chart.js. Sem isso, a IA pode entregar React.
  • ›Layout numerado: 5 regiões específicas. Reduz ambiguidade.
  • ›"Reagem em tempo real": critério de aceite testável.
  • ›try/catch obrigatório: blindagem contra erros de gráficos individuais.
  • ›"Sem chamadas de rede": garante que abre direto, sem servidor.

Critério de sucesso explícito

Termine o prompt com um critério testável:

"Critério de aceite: ao abrir o arquivo no Chrome, todos os filtros funcionam, todos os gráficos renderizam, a tabela mostra dados filtrados, e o console fica sem erros."

Critério testável = critério útil. Sem ele, a IA decide o que "funcionar" significa.

Lição prática

No último prompt da cadeia, seja específico sobre stack. É aqui que escolhas de tecnologia entram. Antes disso, atrapalham a clareza dos dados.
