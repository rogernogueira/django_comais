Construção · 6.5

Acessibilidade — não é opcional

Dashboard inacessível exclui daltônicos, usuários de teclado, leitores de tela. Pequenos cuidados resolvem 80%.

Mínimos obrigatórios

  • ›Contraste AA (4.5:1): texto sobre fundo precisa contrastar. Ferramenta: contrast-ratio.com.
  • ›Acessível por teclado: Tab para navegar, Enter para confirmar. Filtros precisam ser <select> nativos.
  • ›Canvas com aria-label: cada gráfico tem rótulo textual descrevendo seu conteúdo.
  • ›Ícones com aria-hidden: ícones decorativos devem ser ignorados pelo leitor de tela.
  • ›Foco visível: nunca remover outline sem substituir por outro indicador.

Cor — cuidados extras

  • ›Não use só cor para distinguir categorias — adicione padrão, ícone ou rótulo. 8% dos homens são daltônicos.
  • ›Vermelho × verde é a combinação mais problemática. Prefira vermelho × azul.
  • ›Paleta acessível (ColorBrewer, Viridis): cores distinguíveis em monocromia também.

Tamanho de fonte

Elemento Mínimo
Corpo (parágrafo, tabela)14 px
Rótulos pequenos (legenda, eixo)12 px
KPI número (destaque)28 px+
Título do dashboard22 px+

Alternativa textual aos gráficos

A tabela detalhada é também uma forma de acessibilidade. Quem não enxerga o gráfico ainda consegue ler os números.

Em casos críticos, adicione um <p> resumindo o gráfico ("3 unidades concentram 80% dos achados pendentes").

Lição prática

Acessibilidade não é "ramp para cadeirante" — é fundação do bom design. Dashboard acessível costuma ser mais claro também para quem não tem deficiência.
