Reatividade em tempo real

Toda mudança de filtro recalcula tudo. Se um componente não reage, é bug — não é feature.

Princípio: fonte única de verdade filtrada

Toda renderização (KPIs, gráficos, tabela) parte do mesmo conjunto filtrado de dados. Quando o usuário muda um filtro, esse conjunto recalcula, e cascateia para tudo.

Arquitetura mínima em vanilla JS

// 1. Estado dos filtros
const FILTERS = {
  unidade: [], tema: [], categoria: [],
  impacto: [], situacao: []
};

// 2. Função pura: aplica filtros e devolve subconjunto
function filtered() {
  return DATA.filter(row =>
    Object.entries(FILTERS).every(([key, vals]) =>
      vals.length === 0 || vals.includes(row[key])
    )
  );
}

// 3. Orquestrador: recalcula tudo
function refreshAll() {
  const data = filtered();
  renderKPIs(data);
  renderCharts(data);
  renderTable(data);
}

// 4. Cada filtro do DOM dispara refresh
document.querySelectorAll('select').forEach(sel =>
  sel.addEventListener('change', e => {
    FILTERS[e.target.id] = Array.from(e.target.selectedOptions).map(o => o.value);
    refreshAll();
  })
);

O que pode dar errado

  • ⚠Algum render usa DATA global em vez do parâmetro data — fica "preso" no estado inicial.
  • ⚠Chart.js não é destruído e re-renderizado — gráfico antigo persiste sobreposto.
  • ⚠Tabela só repinta a parte visível — drill-down some.
  • ⚠Erro em um render quebra toda a cadeia — proteja com try/catch.

Lição prática

Teste de aceitação: selecione um filtro e veja se TUDO muda. Se KPIs mudam mas o gráfico não, ou se a tabela atualiza mas o donut não, há acoplamento errado. Toda renderização deve receber data como argumento.
