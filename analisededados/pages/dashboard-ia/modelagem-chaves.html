Modelagem · 3.2

Chaves estrangeiras — a costura entre tabelas

É o que permite ligar "esta recomendação" a "aquele achado" e fazer drill-down funcionar.

Exemplo: relação 1:N

tabela_achados.csv
  codigo, categoria, tema, ...
  2.1.1,  corrigida, estoques, ...
  2.2.1,  pendente,  imoveis,  ...
  2.4.4,  inconformidade, transferencias, ...

tabela_recomendacoes.csv
  id,       achado_codigo,  estagio,         prazo
  1707415,  2.4.4,           em_atendimento,  2025-12-31
  1707501,  2.2.1,           emitida,         2026-06-30

  └──> "achado_codigo" aponta para "codigo" na tabela_achados

Regras de ouro

  • ›Nome indica a referência: use achado_codigo (não codigo) no lado "filho" da relação.
  • ›Mesmo tipo dos dois lados: se o pai é string, o filho também é. Se um é "2.1.1" e outro 211, o join quebra.
  • ›Integridade referencial: toda chave estrangeira deve existir no pai. Linha "órfã" é bug.
  • ›Sem duplicatas no pai: chave única do lado "1" da relação 1:N.

Validação rápida em JavaScript

// Toda recomendação aponta para um achado existente?
const achadoCodigos = new Set(ACHADOS.map(a => a.codigo));
const orfas = RECOMENDACOES.filter(r => !achadoCodigos.has(r.achado_codigo));

if (orfas.length > 0) {
  console.warn("Recomendações órfãs:", orfas);
}

Lição prática

Chave estrangeira é um contrato entre tabelas. Sem ele, drill-down vira "tudo aparece" ou "nada aparece". Confira a integridade antes de codar a interface.
